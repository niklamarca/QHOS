## B. Explanation of the prior test-count discrepancy

Two different things were being compared as if they were one number.

**552 vs 553 (same selector, previous phase).** The intermediate count was taken
after the Hybrid-value tests were added but while
`test_runtime_artifacts_and_test_scratch_stay_out_of_source_control` still
raised `NameError: Path is not defined`. Fixing the import made that one test
pass. 552 + 1 = 553. Determined from the previous phase's own traceback, not
guessed.

**553 vs 567 (different selectors).** The previous phase reported a
"Brain-related" count from a keyword filter across *all* of `tests/`:

```
-k "brain or discovery or attest or soak or replay or shadow or cognitive
    or fable or committee or sandbox or control_plane or language or proving
    or calibration or fault or provider or hybrid"
```

That selector includes tests in `test_language_contract.py`,
`test_model_committee.py` and any other file whose name or test name matches
those words. It is a different population from `tests/test_brain*.py`.

Re-running the old keyword selector on this revision produces **613 passed**.
613 − 553 = 60, which is the architecture-contracts suite added this phase.
The glob selector of `test_brain*.py` produces **567**, because it excludes the
non-`test_brain*` files the keyword filter was picking up.

The 553 number was never an RC baseline. It cannot be compared to 567. Both
are recorded; only 567 is authoritative.

The RC manifest previously stored 563 / 710 from an earlier emit on this same
SHA before the last four architecture-contract tests landed. This emit
replaces that with 567 / 714, reproduced.

## AA. Telemetry-quality contract

`TelemetryQualityIssue` is first-class and distinct from Incident: it describes
a defect in the *signal*, not in the component the signal is about. Evidence
carries source, expected vs actual freshness, and the conflicting healthy
self-report when one exists. Severity follows attestation context (dev
informational, production candidate-eligible). It enters Improvement
Intelligence as `OBSERVABILITY_IMPROVEMENT_CANDIDATE`, never as a patch.
